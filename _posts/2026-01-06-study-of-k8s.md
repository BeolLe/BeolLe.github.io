오늘은 쿠버네티스에 대해 간단하게 공부했다.

1. 쿠버네티스란?
    - Kubernetes(K8s)라고도 부름. 컨테이너화한 앱의 배포, 확장, 관리 등을 자동화하는 오픈소스 플랫폼으로 컨테이너 오케스트레이션 시스템.
    - 어제 공부한 도커로 만든 이미지를 실행하고 배포하고 관리하는 도커의 다음 단계라고 볼 수 있음.

2. 쿠버네티스의 종류
    - Minikube : 설치가 쉬운만큼 구조가 단순하고, 연습하기 좋음. 오늘은 이걸로 공부해봄.
    - Kind(Kubernetes in docker) : 도커 컨테이너를 서버인 척 띄워 멀티노드 환경을 구현함. 로컬 테스트용으로 나쁘지 않음. 내일은 이걸로도 해볼 예정.
    - EKS / GKE : AWS, 구글에서 관리하는 서비스로 유료임.(실무에서 사용하지 않을까 싶음)
    - Kubeadm : 리눅스에 하나하나 설치해서 공부용으로는 좋지만 어려울 수 있음.

3. 쿠버네티스의 기본 구조
    - Pod : 일반적으로 1개의 컨테이너를 뜻하지만, 목적에 따라 여러 개의 컨테이너를 하나처럼 엮을 수 있음. 이를 사이드카 패턴이라고 하는데, 여러 개의 컨테이너를 엮어 하나처럼 만든 것임.
    - Node : 실제 컴퓨터 즉 서버를 이야기 하는 것임. 만약 5개의 컴퓨터로 쿠버네티스를 구성한다면, 총 5개의 노드가 있는 것임. 단 노드는 마스터(Control Plain 이라고도 함)와 워커로 나뉨.
        - Master Node : 명령을 해석하고, 한가한 노드에 일을 배분함. 단, 마스터가 1대일 때 죽으면 서버 자체가 좀비가 되기 때문에 홀수를 주로 사용하며, 3대 중 1대가 죽어도 2대가 과반수 결정으로 시스템을 유지할 수 있고, 만약 2대로 구성했을 때 1대가 죽으면 5:5로 의사결정이 되지 않아 똑같이 시스템 먹통이 발생함.
        - Worker Node : 실제로 일을 수행하는 서버로, 마스터의 명령을 받아 일을 함. 

4. 기본 명령어
    - kubectl get pods: 현재 실행 중인 포드(작업자) 목록 조회
    - kubectl get all: 포드, 서비스, 디플로이먼트 등 전체 현황판 조회
    - kubectl logs [포드이름]: 포드의 업무 일지(로그) 확인 (에러 잡을 때 필수)
    - kubectl describe pod [포드이름]: 포드의 상세 상태표 확인 (왜 죽었는지, 이미지는 잘 당겨왔는지)
    - kubectl exec -it [포드이름] -- /bin/bash: 포드 내부로 직접 침투 (접속)
    - kubectl delete pod [포드이름]: 포드 강제 삭제 (삭제하면 관리자가 알아서 새것으로 교체함 = 재시작)

오늘은 맥북에서 미니큐브를 설치해서 스트림릿 이미지 만들어 둔 것을 활용했다.

다만, M1 기본사양 맥북프로로는 여러 개의 노드를 돌리기 어려울 것 같아, 내일은 윈도우와 맥, 리눅스 전부를 사용해서 쿠버네티스를 한번 활용해볼까 싶다.

또한 어제 도커에서 만들어둔 스트림릿 대시보드를 활용해서 맥북에서 열어보려고 했었는데, 지금 내 맥은 ARM64라서 하드웨어 차이에서 오는 문제때문에 로제타 위에서 돌아가서 대시보드가 상당히 느린 문제가 있었다.

그래서 도커에서 다시 한번 linux/amd64 가 아니라 linux/arm64 를 활용해 이미지를 굽고, 받아오는 방법을 알게 되었다.

간단하게 제미나이와 공부했는데, 생각보다 오늘은 공부에 집중을 못했다.
