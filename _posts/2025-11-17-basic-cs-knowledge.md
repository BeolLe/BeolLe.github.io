# 이 공부를 시작한 계기
나는 데이터 분석가 부트캠프를 해본 사람이다. 또한 데이터 엔지니어 직무도 함께 희망하는 사람이다.
특히나 메타 캐글이라는 대회를 참여하면서 느낀 점은, 내가 이 데이터가 정확히 어떤 구조를 통해 처리가 되는지 모르는 것이 취약하다는 점이다.

데이터 분석 부트캠프를 보면 흔히 써있는 말이 있다.
SQL언어를 통해 분석도 하고, Pandas라는 라이브러리를 통해서 분석하기도 하고, 스파크처럼 분산처리 방법으로 분석하기도 한다는 점이다.

자, 근본적인 궁금증으로 돌아가서 이들의 차이가 단순히 이 정도로 설명을 할 수 있는 것인가?
나는 아니라고 생각한다.

SQL은 데이터베이스를 가지고 있는 서버에 요청을 하는 것인데, 쿼리문의 작성 방식에 따라 서버에 부하가 걸려 다른 접속자들이 이용하기 어렵게 만들 수 있다.
Pandas같은 라이브러리는 데이터를 전부 메모리에 올려두어 처리를 하기 때문에, 이는 대용량일 수록 그만큼의 메모리가 필요하다는 한계가 있다.
Spark같은 방식은 분산처리로 유명한 방식이지만, 이 또한 메모리가 많이 필요하며, 여러 대의 컴퓨터로 처리를 하고 합치는 과정이 필요하기 때문에 빠른 실시간 처리에는 구조상 한계가 있다.

위를 검색해보면 흔히 나오는 이야기이다.
근데 공부를 하다가 느낀 점은 이는 근본적으로 각 처리방식에 차이가 있는 것이고, 이를 자세히 이해하려면 기본적인 하드웨어 구조부터 알아야한다는 생각이 들었다.

따라서 오늘은 근본적인 컴퓨터의 구조에 대해 공부하려고 한다.

# 1. CPU에 대해서
먼저 컴퓨터의 두뇌라고 불리는 CPU에 대해서이다.

간단하게 말하면, CPU는 Central Processing Unit의 줄임말로, 대부분의 연산과 명령 처리를 담당하는 부품이다.
흔히 우리는 코어와 스레드에 대해서만 생각을 하지만, 근본적인 구조에 대해 더욱 깊이 생각해볼 필요가 있다고 생각한다.

## 1-1. CPU의 기본 개념
    1. CPU란 무엇인가
    CPU는 여러 개의 회로들의 집합체로 구성된 프로세서이다.
    ALU, CU, Register 등의 구조로 이루어진 코어를 여러 개 두고, 대체로 L1, L2를 코어의 개별 캐시로 L3같은 경우는 공용 캐시로 두고 사용한다.(자세한 내용은 아래에서 공부해보겠다.)
    
    CPU는 이런 구조들이 프로그램 명령어를 순차적으로 실행하는 프로세서이다.

- 프로그램 실행 과정
    1. 명령어 가져오기(Fetch)
        - 프로그램 카운터(PC > Program Counter)[^1]가 가리키는 메모리 주소에서 명령어를 가져온다.
    2. 명령어 해독하기(Decode)
        - 제어 장치(CU > Control Unit)[^2]가 명령어를 해석하고, 필요한 실행 유닛에 전달할 제어 신호를 생성한다.
    3. 명령어 실행하기(Execute)
        - 실행 장치(EU > Execution Unit)[^4]가 데이터를 처리하여 결과를 저장한다.
    4. 결과 저장하기(Write Back)
        - 연산 결과를 레지스터 또는 메모리에 저장한다.

- 명령어 집합(ISA)의 개념과 작동방식
    ISA(Instruction Set Architecture)란 마이크로프로세서[^5]가 이해하고 실행할 수 있는 기계어 명령어를 뜻한다.
    1. CISC와 RISC
        ISA를 설계하고 구현시키는 대표적인 컴퓨터 아키텍쳐 방식이다. 
        1-1. CISC(Complex Instruction Set Computer) > 복잡한 명령어 집합 컴퓨터
            - 명령어의 길이가 정해져 있지 않아, 가변적인 명령어 하나로 여러 단계의 연산을 수행할 수 있게 설계되었다. 옛날에는 여러 단계에 거칠 작업을 한 번에 끝낼 수 있다. 이는 명령어 밀도[^6]가 뛰어나다는 뜻으로, 메모리 비용 절감 및 용량 절약에 효과적이다.

            - 다만 구조가 복잡하여 프로세서 설계가 힘들다. 길이가 가변적이어서, 명령어 디코더의 설계를 어렵게 만들었다. 길고 복잡한 명령어의 시작과 끝을 올바르게 식별하고 명령어를 올바르게 해석할 수 있게 설계해야했기 때문이다. 그 뿐 아니라 복잡한 명령어 세트가 프로세서의 전체적인 크기와 전력 소비량을 늘렸다. 그 뿐 아니라, 어떤 길이의 명령어가 입력될 지 몰라 파이프라이닝[^7] 구현이 매우 어렵다.
        1-2. RISC(Reduced Instruction Set Computer) > 축소된 명령 집합 컴퓨터
            - CISC의 문제점을 해결하기 위해 제작되었다. 명령어 길이를 일정하게 정의하고 포맷도 일정하게 다듬어 파이프라인 효율을 높였다. 이로 인해 디코더도 단순화되고, 하드웨어의 복잡성도 줄어 칩 설계의 간소화 및 제조 비용 감소에 큰 역할을 하였다. 그 뿐 아니라, 배터리 수명을 연장시키고, 운영 비용을 낮췄다. 일정한 길이의 명령어는 프로그램의 실행 시간 예측과, 성능 최적화를 위한 컴파일러를 개발하는 데에 도움을 주었다.
            그 뿐 아니라, 메모리 대상 연산을 load/store 연산만 가능하게 한정하고 나머지는 레지스터를 사용하여 레이턴시를 낮추고, 명령어 낭비를 줄였다.

            - 단 RISC의 명령어가 적지만은 않다. RISC의 개발 목적은 명령어를 줄이는 것과 피연산자 지정 모드[^8]를 줄이는 것도 같은 목표였으나, 성능을 희생하여 다른 명령으로 쉽게 대체할 수 없는 명령을 없애지는 않아 현재는 명령어가 천 개가 넘는 것까지 존재하며, 목적에 따라 다양한 명령어를 쓸 수 있다. 저전력이라는 말 또한 상대적 개념일 뿐이다. 디코더는 CPU에서 면적도 크지 않고, 전력도 1% 정도만 소모하기 때문이다. 전력 소모는 동작 전압 및 공정 등 다양한 요소가 더욱 크게 영향을 준다.



[^1] : PC : 프로그램 계수기라고도 부르며, 수행될 명령이 들어있는 주 기억장치(메모리)의 주소를 기억하는 레지스터이다. IC(Instruction Counter) 혹은, LC(Location Counter)라고도 부른다.
[^2] : CU : ID로부터 보내진 신호에 따라 명령어를 실행하는 제어장치이다. clock[^3]에 의해 발생한다.
[^3] : clock : CPU가 순차적으로 동작할 수 있게 만드는 타이밍 신호를 뜻한다. 1초에 10억번 신호를 발생하면 1GHz의 CPU인 것이다. 이론상으로는 1클락당 프로그램 실행 과정이 1단계씩 진행되지만, 실제로는 분기 예측 실패나, 자원 충돌등의 이유로 1단계씩 움직이지 않을 수 있다.(해당 내용은 추후 자세히 다룰 예정)
[^4] : EU : 작업과 계산을 수행하는 장치로, ALU나 FPU, Load/Store Unit 등 명령 실행에 필요한 연산 장치를 가질 수 있다.
[^5] : 마이크로프로세서 : 여러 칩으로 나뉘어 있던 CPU의 기능을 단일 IC로 통합한 칩을 의미한다. 현대의 CPU는 대부분 MPU(MicroProcessor)의 형태로 제작된다.
[^6] : 명령어 밀도 : 명령어가 동일한 기능을 얼마나 적은 공간에 표현할 수 있는지, 즉 메모리 사용 효율을 나타내는 개념이다.
[^7] : 파이프라인 : 여러 명령어의 서로 다른 단계를 동시에 처리하여 전체 처리량을 높이는 프로세서 동작 방식이다.
[^8] : 피연산자 지정 모드 : 연산에 필요한 데이터를 레지스터에서 가져올지, 메모리에서 가져올지, 오프셋·간접 주소 등 어떤 방식으로 참조할지를 규정한 방식이다.
