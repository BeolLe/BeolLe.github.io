# 1. CPU에 대해서
먼저 컴퓨터의 두뇌라고 불리는 CPU에 대해서이다.

간단하게 말하면, CPU는 Central Processing Unit의 줄임말로, 대부분의 연산과 명령 처리를 담당하는 부품이다.
흔히 우리는 코어와 스레드에 대해서만 생각을 하지만, 근본적인 구조에 대해 더욱 깊이 생각해볼 필요가 있다고 생각한다.

## 1-1. CPU의 기본 개념
    1. CPU란 무엇인가
    CPU는 여러 개의 회로들의 집합체로 구성된 프로세서이다.
    ALU, CU, Register 등의 구조로 이루어진 코어를 여러 개 두고, 대체로 L1, L2를 코어의 개별 캐시로 L3같은 경우는 공용 캐시로 두고 사용한다.(자세한 내용은 아래에서 공부해보겠다.)
    
    CPU는 이런 구조들이 프로그램 명령어를 순차적으로 실행하는 프로세서이다.

### - 프로그램 실행 과정
    1. 명령어 가져오기(Fetch)
        - 프로그램 카운터(PC > Program Counter)가 가리키는 메모리 주소에서 명령어를 가져온다.
    2. 명령어 해독하기(Decode)
        - 제어 장치(CU > Control Unit)가 명령어를 해석하고, 필요한 실행 유닛에 전달할 제어 신호를 생성한다.
    3. 명령어 실행하기(Execute)
        - 실행 장치(EU > Execution Unit)[^1]가 데이터를 처리하여 결과를 저장한다.
    4. 결과 저장하기(Write Back)
        - 연산 결과를 레지스터에 저장한다.

### - 명령어 집합(ISA)의 개념과 작동방식
    ISA(Instruction Set Architecture)란 마이크로프로세서[^2]가 이해하고 실행할 수 있는 기계어 명령어를 뜻한다.
    1. CISC와 RISC
        ISA를 설계하고 구현시키는 대표적인 컴퓨터 아키텍쳐 방식이다. 
        1-1. CISC(Complex Instruction Set Computer) > 복잡한 명령어 집합 컴퓨터
            - 명령어의 길이가 정해져 있지 않아, 가변적인 명령어 하나로 여러 단계의 연산을 수행할 수 있게 설계되었다. 옛날에는 여러 단계에 걸칠 작업을 한 번에 끝낼 수 있다. 이는 명령어 밀도[^3]가 뛰어나다는 뜻으로, 메모리 비용 절감 및 용량 절약에 효과적이다. 

            - 다만 구조가 복잡하여 프로세서 설계가 힘들다. 길이가 가변적이어서, 명령어 디코더의 설계를 어렵게 만들었다. 길고 복잡한 명령어의 시작과 끝을 올바르게 식별하고 명령어를 올바르게 해석할 수 있게 설계해야했기 때문이다. 그 뿐 아니라 복잡한 명령어 세트가 프로세서의 전체적인 크기와 전력 소비량을 늘렸다. 그 뿐 아니라, 어떤 길이의 명령어가 입력될 지 몰라 파이프라이닝[^4] 구현이 매우 어렵다.
        1-2. RISC(Reduced Instruction Set Computer) > 축소된 명령 집합 컴퓨터
            - CISC의 문제점을 해결하기 위해 제작되었다. 명령어 길이를 일정하게 정의하고 포맷도 일정하게 다듬어 파이프라인 효율을 높였다. 이로 인해 디코더도 단순화되고, 하드웨어의 복잡성도 줄어 칩 설계의 간소화 및 제조 비용 감소에 큰 역할을 하였다. 그 뿐 아니라, 배터리 수명을 연장시키고, 운영 비용을 낮췄다. 일정한 길이의 명령어는 프로그램의 실행 시간 예측과, 성능 최적화를 위한 컴파일러를 개발하는 데에 도움을 주었다.
            그 뿐 아니라, 메모리 대상 연산을 load/store 연산만 가능하게 한정하고 나머지는 레지스터를 사용하여 레이턴시를 낮추고, 가변 길이 명령어의 비효율을 줄였다.

            - 단 RISC의 명령어가 적지만은 않다. RISC의 개발 목적은 명령어를 줄이는 것과 피연산자 지정 모드[^5]를 줄이는 것도 같은 목표였으나, 성능을 희생하여 다른 명령으로 쉽게 대체할 수 없는 명령을 없애지는 않아 현재는 명령어가 천 개가 넘는 것까지 존재하며, 목적에 따라 다양한 명령어를 쓸 수 있다. 저전력이라는 말 또한 상대적 개념일 뿐이다. 디코더는 CPU에서 면적도 크지 않고, 전력소모 비중도 매우 낮기 때문이다. 전력 소모는 동작 전압 및 공정 등 다양한 요소가 더욱 크게 영향을 준다.
        
    2. x86과 ARM
        2-1. x86
            - CISC를 사용하는 아키텍쳐로, 개인용 컴퓨터나 서버, 워크스테이션 등 다양하게 이용된다. 고성능을 달성하기 위한 CISC는 전력 소모가 높고, 디코더의 설계를 복잡하게 만들며 칩 설계의 난이도를 높이고 제조 비용을 증가시킬 수 있다. 여기까지는 기본적인 CISC의 특징이다.
            - 메인보드 + CPU 및 각종 컨트롤러들이 분리된 구조로 발전해왔다. 이 때문에 하드웨어의 조합ㅂ이 너무 다양해서 각 장치에 알맞는 드라이버를 설치해야 한다는 불편한 점이 있다.
            - 첨언으로 x86의 이름의 유래는 당시 CPU가 86으로 끝나는 모델들이었기 때문에 붙은 이름이다.
        2-2. ARM > Advanced RISC Machine
            - RISC를 사용하는 아키텍쳐로, 높은 에너지 효율성과 상대적으로 저전력이라는 장점이 있다. CISC에 비해 고성능 컴퓨팅의 제약이 있고(현재는 과거형), 소프트웨어 개발자의 고급 기능 구현에 어려움을 만들 수 있다. 다만, 최근에는 단순히 컴퓨팅 성능만 따지지 않고 에너지 효율성까지 고려하는 만큼 점점 사용량이 늘고 있으며, 성능면에서도 이전보다 진보된 면을 보여주고 있다. 여기까지는 기본적인 RISC의 특징이다.
            - 기본적으로 SoC(System on Chip)[^6]의 구조를 가지고 있다. 기본적으로 제조사에서 드라이버를 제공하고, 칩의 구조상 x86에 비해 상대적으로 하드웨어 구성이 고정되어 있어 호환이 매우 잘 되는 편이다.
    
## 1-2. CPU의 구성요소
    CPU에 대한 이해를 바로잡기 위해 코어 내부를 우선 살펴보려 한다.

### - CPU 코어의 구성 요소
    1. ALU(Arithmetic Logic Unit) > 산술 논리 장치라고도 말한다.
        - CPU에서 산술 연산(사칙연산)과 논리 연산(AND, OR, XOR, NOT)을 수행하는 장치이다. 이는 단순히 CPU 뿐 아니라 GPU, TV, 디지털 시계 등 대부분의 디지털 기계에 들어가있다.

    2. CU(Control Unit)
        - CU는 IR에 저장된 명령어를 내부의 ID(Instruction Decoder)가 해석한 신호에 따라 제어 신호를 보내 명령어를 실행하는 제어장치이다.

    3. Register
        - 레지스터는 명령이나 연산 결과를 임시 저장하는 장치이다. CPU에 주로 사용하는 레지스터의 종류 중 일부는 아래와 같다.
            - PC(Program Counter) : 프로그램 계수기라고도 부르며, 수행될 명령이 들어있는 주 기억장치(메모리)의 주소를 기억하는 레지스터이다. IC(Instruction Counter) 혹은, LC(Location Counter)라고도 부른다.
            - IR(Instruction Register) : 메모리에서 가져온 현재 실행중인 명령어를 저장한다.
            - MAR(Memory Address Register) : 메모리에서 읽거나 쓸 주소를 저장한다.
            - MBR(Memory Buffer Register)/MDR(Memory Data Register) : 메모리에서 읽거나 메모리에 쓸 데이터를 임시 저장한다.
            - GPR(General Purpose Register) : 연산에 필요한 데이터를 저장하는 다목적 레지스터이다.

    4. Clock과 Cycle
        4-1. Clock
            - CPU가 순차적으로 동작할 수 있게 만드는 타이밍 신호를 뜻한다. 1초에 10억번 신호를 발생하면 1GHz의 CPU인 것이다. 초기 CPU의 경우에는 1클락당 프로그램 실행 과정이 1단계씩 진행되었으나, 현대의 CPU는 파이프라이닝 덕분에 여러 명령어가 동시에 여러 단계에서 흘러간다.
        4-2. Cycle
            - Cycle은 클락 신호 1번을 받아 내부 상태가 한 번 변화하는 단위를 말한다. 어떤 동작을 수행하느냐에 따라 1번의 클락이 필요할 수도, 4번의 클락이 필요할 수도 있다. 따라서 이것들의 평균을 내 CPU의 성능 지표로 활용할 수 있는 것이 CPI(Cycles Per Instruction)이다. 
        4-3. CPI
            - CPI는 각 동작별로 필요한 클락 수가 달라, 평균을 낸 지표다. 고성능 CPU는 보통 1 이하를 목표로 설계한다. 틱 1번에 여러 명령어를 동시에 완료할 때 파이프라이닝이 잘 되어있거나, 슈퍼스칼라의 구조를 가진 성능 좋은 CPU의 경우 CPI가 0.25나 더 아래로 떨어질 수 있고, 반대로 병목 현상이나 메모리 지연이 많아지면 1보다 커진다.
    
## 1-3 명령 처리 속도를 높이는 기술
    CPU에서 클럭이나 사이클 뿐 아니라 속도 최적화 기술이 CPU의 성능을 결정짓는데, 아래와 같은 기술들이 주요한 역할을 한다.

    1. 파이프라이닝(Pipelining)
        - 명령어의 데이터 경로를 세분화하고, 각기 다른 세부 단계를 동시에 수행함으로써 여러 명령어들을 중첩 수행하여 성능 향상을 하는 방법이다. 이 방법을 어렵게 만드는 원인들이 있는데 이들을 해저드라고 하는데, 자세한 내용은 링크 16번을 참고하자.

    2. 분기 예측(Branch Prediction)
        - CPU에 다음 명령을 할 때 여러 가지 선택지가 있는 경우, 결과를 예측해서 명령어를 가져와 파이프라인 내 레지스터나 버퍼 등에 명령어를 저장해두었다가, 결과가 나오는 즉시 사용할 수 있게 만드는 방법이다. 사실 명령어를 가져오는 시간 자체는 느리지 않지만, CPU가 3GHz일 때 1사이클 당 0.3ns밖에 최대한 빠르게 접근해야 한다. 추가로 최근의 분기 예측은 일반적으로 95% 이상의 정확도를 가진다.
        - 분기 예측의 정확도를 높이기 위해 프로그램에 있는 분기 패턴을 예측기가 학습하거나 히스토리를 저장해서 맞출 수 있으며, 컴파일러가 branch를 최소화하도록 코드를 재정렬 하고, 분기 예측 당시에도 예측이 틀릴 경우를 대비하여 패널티를 최소화하는 구조가 있어서 매우 효과적인 방법 중 하나다.
        - 첨언하자면 가장 기본적인 방법이 분기 예측이고 이보다 발전된 방식이 여러 개 있는데 관심이 있다면 17번 링크를 확인해보자.

    3. Out-of-order Execution > 비순차적 명령어 처리
        - CPU가 특정한 종류의 지연으로 인해 낭비될 수 있는 명령 사이클을 이용하는 방법이다. 기본적으로 파이프라인은 명령어를 순서대로 처리했는데, 사이클이 낭비되는 것을 막고 명령 실행 효율을 높이기 위해 순서를 따르지 않고 처리하는 기법이다. 다만 최종적으로는 프로그램 원래 순서를 유지하여, 겉으로 보기에는 순차적으로 실행된 것 처럼 보이게 만든다.
        - 예시를 들자면 명령을 여러 개(A,B,C,D) 내렸을 때, B는 A의 명령과 관련이 있지만 C가 A,B 두 개의 명령과 서로 무관하다면 A의 명령이 멈춰있을 때와 같은 상황에서 C의 명령을 수행할 수 있게 해야한다. 

    4. SuperScalar 
        - 슈퍼스칼라는 CPU 내에 파이프라인을 여러 개 배치하여 명령어를 동시에 처리하는 기술이다. 파이프라인이 하나라면 클락 당 하나의 명령어를 수행하고, 2개라면 이상적으로 클락 당 2개의 명령어를 처리할 수 있다. 일반적으로 슈퍼스칼라는 동시에 처리가 가능한 명령어 갯수에 따라 N-이슈, N-와이드, N-웨이(셋 다 동일하지만 학계와 업계에서 선호하는 명칭이 다른 듯 하다.)의 슈퍼스칼라라고 표현 가능하다.
        - 예시를 들자면 위의 Out-of-order Execution의 예시에서 D의 명령 또한 A,B,C와 무관하다면 C와 D를 동시에 처리할 수 있다면 이를 슈퍼스칼라라고 한다.

## 1-4 CPU 캐시 구조(L1/L2/L3)
    CPU와 메모리 사이의 병목을 해결하기 위한 구성요소로, 데이터 처리 속도에 결정적인 영향을 준다.
    
    1. 캐시가 필요한 이유
        - 과거의 CPU와 메모리의 클록 속도 차이가 지금보단 크진 않았으나, 점차 속도 차이가 벌어지며 메모리에서 시간을 읽고 쓰는 것이 점점 오래 걸리기 시작했다. 당시에도 캐시는 존재했으나, 기술 부족으로 인해 L2 캐시가 메인보드에 있었고 CPU내부에는 존재하지며 않았으나 현재에는 대부분의 CPU안에 캐시가 들어있다. 이렇게 CPU 메모리 계층 구조에서 속도, 공간, 가격 차이가 있는 두 계층 혹은 소프트웨어에서도 캐시를 찾아볼 수 있다. 
        - 하지만 흔히 쓰이는 DRAM은 Row/Column 접근 방식, Sense Amplifier, Precharge, Refresh가 필요해 구조적으로 CPU 내부에 넣어도 느려 일반적으로 SRAM을 캐시로 사용한다. 구조적으로 DRAM은 메모리 용량이 크지만 느리고, 저렴하다는 장점이 있다.
        - 캐시는 데이터 사용의 지역성 이라는 특성을 이용하는데, 각각 시간적 지역성과 공간적 지역성이 있다. 시간성 지역성은 지금 특정 데이터를 사용하면 가까운 미래에 다시 사용할 확률이 높다는 것이고, 공간적 지역성은 어떤 데이터가 사용된다면 그와 인접한 데이터에 접근할 확률이 높다는 것으로, CPU 캐시는 이를 효과적으로 이용한다.

    2. L1/L2/L3 캐시의 역할
        - 우선 L1,L2,L3에서 L이란 Level을 뜻하며, L1에서 L2, L2에서 L3로 점차 데이터를 찾아나가면서 최종 캐시인 LLC(Last Level Cache)까지도 데이터가 없다면 메모리 계층에서 찾게된다.SRAM의 경우 용량과 접근 속도에서 반비례 관계(트레이드 오프라고도 한다.)에 있기 때문에 여러 개의 계층으로 나누어 성능을 올렸다.
        - L1 Cache
            - 코어 내부에 위치하며, 가장 빠른 캐시로 용량은 보통 코어당 32~64kb 수준으로 작은 편이다. 즉시 접근해야하는 데이터나 명령어를 저장한다.
            - 추가로 데이터 캐시와 명령 캐시 두 섹션으로 나뉘는 캐시이다. 
        - L2 Cache
            - 코어 내부 또는 코어 근처에 존재하며 L1보다 느린 캐시로 L1에서 미스 난 데이터를 공급한다. 용량은 코어 당 256kb에서 1mb 정도를 보통 가진다.
        - L3 Cache
            - 일반적으로 가장 낮은 수준의 캐시로, CPU 당 1개로 공유 캐시로 쓰인다. L2보다 느리지만 상대적으로 큰 몇mb~몇백mb 수준의 용량이 있으며, 코어 간 데이터를 교환하거나, 캐시 일관성 유지 및 DRAM 접근 횟수를 최소화하는 역할이다. 싱글 코어일때에는 하나의 블록 형태였으나, 코어의 갯수가 증가하면서 하나의 캐시 조각이 물리적으로 분산배치되면서 코어 당 하나의 슬라이스가 대응되지만 전용으로 할당되는 것은 아니고, 먼저 접근하려는 경향이 있다.

    3. 캐시 히트/미스 개념
        - Cache Hit
            - CPU가 요청한 데이터가 CPU 캐시에 있을 때 캐시 히트라고 한다. L1부터 L2, L3 까지의 순서대로 탐색을 한다. 일반적으로 캐시 크기가 늘어나면 캐시 적중률이 올라가며 성능에 긍정적인 영향을 끼친다.
        - Cache Miss
            - CPU가 요청한 데이터가 캐시에 없어 주 메모리에서 캐시를 로드하도록 요청하는 것이 캐시 미스라고 한다. 이는 캐시에 부정적인 영향을 미친다.

    4. 코어 간 캐시 일관성(Coherency)
        - 여러 로컬 캐시에 저장된 공유 리소스 데이터의 균일성을 의미한다. 즉 코어 별 캐시 메모리를 가진 시스템에서는 공유 데이터의 복사본이 여러 개 존재할 수 있는데, 이 중 하나가 변경되면 다른 복사본도 변경 사항을 반영할 수 있어야 한다. 이를 쓰기 전파라고 한다. 또한 순서가 틀어지지 않게 단일 메모리 위치에 대한 읽기/쓰기는 모든 프로세서에 의해 동일한 순서로 보여야 하는데, 이는 쓰기 직렬화라고 한다.

## 1-5 멀티코어와 병렬 처리 구조
    옛날 CPU의 클록 속도 증가에 한계가 오면서, 코어 갯수를 늘리며 병렬 처리를 통해 효율적으로 활용하기 시작했다. 또한 싱글코어의 메모리 병목과 전력 및 발열 문제를 줄이기 위해 현대의 CPU는 대부분 이런 방식으로 제조된다.

    1. 멀티코어 구성 방식
        - 코어 > 위에서 이야기 했던 바와 같이 구성되어 있다.
        - L3 혹은 공유 LLC(L1이나 L2는 대체적으로 코어에 포함되어있음)
        - 메모리 컨트롤러
            - 컴퓨터의 주 메모리로 들어오고 나가는 데이터를 관리하는 회로로, DRAM을 읽고 쓰는데 필요한 논리를 포함해서 메모리 리프레시 및 기타 기능을 제공하는 장치이다. 이런 역할을 하는 장치가 CPU 내부에도 있는데, 이는 CPU와 메모리 간 인터페이스 역할을 한다.
        - 코어 간 연결방법
            a. Symmetric MultiProcessing(혹은 Shared-Memory multiProcessing)
                - 두 개 이상의 코어가 하나의 공유된 메모리를 사용하는 아키텍쳐이다. 모든 코어가 동일한 OS 복사본을 실행하여 동일한 속도와 동일한 접근 권한으로 공유 메모리에 접근하며, 프로세서 간 통신이 공유 메모리를 통해 이루어져 병렬 프로그래밍이 용이하고 작업 분배가 쉬우며, 프로세스 간 데이터 교환 속도가 빠르다.
                - 단일 CPU 내의 멀티코어 구성은 물론, 여러 개의 프로세서(CPU)를 가지는 단일 서버 시스템의 기본 병렬 처리 아키텍쳐로도 활용된다. 단일 서버 시스템에서 활용되는 이유는 구현이 비교적 단순하고, OLTP(Online Transaction Processing)처럼 다수의 사용자가 접근하는 작업에 용이하지만, 모든 코어가 공유 시스템 버스와 메모리에 접근하기 때문에, 코어수가 일정 수준을 넘어서면 버스 병목 현상이 발생하여 확장성의 한계가 명확하다.
            b. Ring Bus(SMP의 구현 방식 중 하나이다.)
                - CPU의 모든 코어, L3 캐시 슬라이스, 메모리 컨트롤러, I/O 유닛과 같은 구성 요소를 양방향의 원형 버스로 연결하는 구조이다. 인접한 코어까지 1클럭 사이클당 1홉(1개의 정거장 개념으로 다음 순서에 도착하는 것을 의미한다)으로 전달된다. 
                - 구현이 단순하고, 코어 수가 적을 때에는 거리가 짧아 지연시간이 낮다. 또한 코어들이 공유 L3 캐시와 다른 구성 요소들의 일관성을 유지하며 빠르게 접근할 수 있게한다.
                - 모든 구성 요소들이 하나의 공유된 버스를 사용하기에 코어 수가 늘어나면 트래픽이 증가해서 버스가 포화되고 병목 현상이 발생한다. 또한, 코어 끼리 통신할 때 제일 먼 코어와 만나기 위해서는 다른 코어를 전부 거쳐야하기 때문에 지연 시간이 코어 수에 비례하여 늘어난다.
            c. 2D Mesh Structure
                - Ring Bus의 단일 통로로 생기는 한계를 해결하기 위해 생긴 구조로, 코어, L3 캐시 슬라이스 등의 노드들을 수직+수평 방향으로 연결하여 평면적인 격자 형태처럼 만드는 구조이다. 단일 경로가 아니라 분산된 통로를 이용하여 트래픽 분산과 수평적 확장과 Ring Bus 대비 높은 대역폭을 통해 병목 현상을 완화할 수 있다.
                - 단 라우터 회로가 필요한데, 이는 설계 및 검증을 복잡하게 만들고 전력 소비가 Ring Bus 대비 증가하며, 특정 노드에 트래픽이 집중되거나, 코어가 적으면 Ring Bus보다 지연 시간이 길 수 있다.
                - 2D Mesh 구조를 수평적으로 연결하면 Torus 형식이 되며, 가장 먼 노드로의 지연 시간을 줄이기 위해 Wrap-around라는 방법으로 가장 자리를 연결하여 순환고리처럼 만들어 지연 시간을 짧게 만든다.
                - 2D Mesh 구조를 수직적으로 연결하면 3D Mesh 형식이 된다. 먼 거리까지 신호를 전송하지 않고, 훨씬 더 많은 통신 채널을 제공하여 일반적인 평면 배선보다 대역폭을 높일 수 있다. 칩들을 수직으로 쌓기 때문에 밀집도를 극대화 할 수 있다. 단 제조가 어렵고, 일부 불량 발생 시 전체를 폐기해야하는 수율 문제, 발열 및 진단의 어려움이 있다.
            d. Core Complex(CCX) + Interconnect Fabric
                d-1. Core Complex(CCX)
                    - CPU 내부의 여러 코어와 로컬 캐시 및 공유 캐시 슬라이스가 하나의 단위로 묶어서 동작하는 것을 코어 클러스터라고 이야기한다. 
                    - 같은 코어끼리는 짧은 경로로 연결되어 통신하면 L3 캐시를 공유하기 때문에 그룹 내부 통신 속도가 빠르다. 또한, 여러 모듈을 여러 개 만들어 연결하는 구조이기 때문에, 불량 시 일부만 다시 제조하면 되서 수율이 좋다. 
                    - 다른 그룹끼리 통신할 때에는 칩 내부의 패브릭을 거쳐야하므로 지연 시간이 길다. 또한 소프트웨어 최적화가 필수이며, 잘 되지 않는다면 오히려 병목현상을 유발할 수 있다.
                d-2. Interconnect Fabric
                    - CPU 칩 내부에서 고속으로 데이터와 명령어가 이동하는 물리적/논리적 통로이다.
                    - 구성 요소를 효과적으로 연결하여 CPU의 코어 수를 쉽게 확장할 수 있게 도와준다. 칩 내에서 초당 테라바이트 급의 높은 전송 대역폭을 지원하며, CPU 설계를 용이하게 만들어준다.
                    - Mesh와 같은 방식은 많은 라우터와 통로를 칩에 구현해야하므로, 칩 면적이 커지고 전력 소비가 많아진다. 또한 HotSpot이 발생할 시 병목현상과 지연 시간 변동이 발생할 수 있다.
            e. NUMA(Non-Uniform Memory Access)
                - 기존 UMA(Uniform Memory Access)[^7] 구조의 한계를 깨트리기 위해 나온 개념이다. CPU당 로컬 메모리를 할당하여 병목 현상을 줄이며, 메모리의 물리적 위치에 따라 접근 시간이 달라지는 구조이다. 하나의 CPU와 직결된 로컬 메모리 영역을 묶어 하나의 NUMA 노드라고 부른다.
                - 병목현상을 해소하고, CPU와 메모리를 더욱 많이 사용할 수 있어 확장성이 좋다. 또한 로컬 메모리 접근 시 지연 시간이 낮고, 노드별 전용 대역폭이 확보되어 전체 시스템의 대역폭을 크게 향상시킨다.
                - 하드웨어 설계가 복잡하고, OS와 메모리 할당자가 NUMA구조를 관리해야한다. 또한 원격 메모리(직결되지 않은 메모리)를 자주 접근할 경우 성능 저하가 발생될 수 있어 최적화가 필수적이다.

    2. 병렬 처리 모델
        2-1. 데이터 병렬성
            - 동일한 작업/명령을 다른 대규모 데이터에 대해 동시에 실행하는 병렬 처리 방식이다. 처리해야 할 거대한 데이터를 독립적인 여러 조각으로 나눠, 각 코어에 할당하여 모두 같은 연산을 병렬로 수행한다. 
            - 데이터가 커질수록 코어 수를 늘려 성능을 선형적으로 확장하기 유리하다. 모든 코어가 같은 연산을 수행하여 CPU의 활용 효율이 높으며, 병렬화 로직이 비교적 간단하여 코드 작성 및 관리가 쉽다.
            - 데이터 크기가 작거나, 분할된 데이터 조각 간 상호 의존성이 높으면 병렬 처리가 어렵고, 모든 데이터에 대해 병렬 연산이 가능한 경우에만 주로 적용이 가능하다. 또한 특정 데이터 조각의 처리가 오래 걸리면 다른 코어가 유휴상태가 될 수 있다.
            - 행렬 곱셈, 벡터 연산, 과학 시뮬레이션, 빅데이터 프레임워크(Spark, Hadoop)에서의 대규모 분산 처리에 활용된다.
        2-2. 작업 병렬성
            - 서로 다른 작업/명령을 서로 다른 코어에 할당하여 동시에 실행하는 병렬 처리 방식이다. 전체 프로그램을 여러 개의 독립적인 함수 또는 스레드로 분할하여 독립적으로 처리한다.
            - 시스템의 다양한 기능을 동시에 처리할 수 있어 시스템의 응답성이 뛰어나다. 작업 간 의존성 문제가 해결된다면 코어 별 독립적인 환경을 제공하여 성능 향상에 도움이 된다.
            - 작업을 완전 독립적이게 나누기 어렵다. 작업간 데이터를 공유할 경우 동기화 문제가 발생할 수 있어, 설계가 복잡해지고 오버헤드가 커진다. 나눌 수 있는 작업 수가 한정되어 있는데, 작업 수가 코어 수 보다 적으면 남는 코어가 발생한다. 또한, 작업마다 필요한 연산 시간이 크게 다르면 짧은 작업을 맡은 코어는 유휴상태가 된다.
            - 멀티태스킹 운영체제, 웹 서버 등 동시성이 중요한 환경에 적합하다.
        2-3. 파이프라인 병렬성
            - 전체 작업을 여러 개의 단계로 나누고, 각 단계를 전담하는 코어나 프로세서에 할당하여 데이터 스트림을 연속적으로 처리하는 방식이다. 
            - 데이터를 스트림 형태로 지속적으로 처리할 때 전체 처리량을 높일 수 있다. 각 단계가 전담 코어를 가지고 있어, 작업 흐름이 체계적이고 관리하기가 쉽다. ETL이나 CPU 명령어 처리처럼 순서가 명확한 작업에 효과적이다.
            - 전체 처리 단계를 거쳐야하기 때문에 단일 데이터 처리 시간은 단축되지 않는다. 또한, 파이프라인에서 가장 느린 단계가 전체 시스템의 속도를 결정짓는 병목이 될 수 있다. 작업을 효율적으로 여러 단계로 나누는 초기 설계가 어렵고, 중간에 단계를 추가하거나 수정하기가 어렵다.
            - ETL을 병렬화 하는 경우에 활용된다.
    3. 멀티 코어가 성능에 미치는 영향
        코어가 늘어나면 성능이 늘어난다고 생각하지만, 무조건적으로 늘어나는 것은 아니다.
        3-1. 코어 수 증가 효과
            - 암달의 법칙에 따르면 어떤 시스템의 성능 향상은 개선된 부분이 사용되는 시간의 비율에 의해 제한된다고 한다. 멀티코어 환경에서 프로그램의 병렬화 불가능한 부분이 코어 수늘 늘려도 성능 향상의 궁극적인 상한선을 결정짓는다고 한다.
        3-2. 메모리 병목과 캐시 구조의 영향
            - 멀티프로세서 시스템에서 캐시를 사용할 때 공유 데이터의 복사본이 여러 곳에 존재하기 때문에 일관성 유지를 위한 통신이 발생하며, 오버헤드의 주된 요인이 된다.
            - 현대 CPU의 경우 메모리보다 처리 속도가 압도적으로 빠르기 때문에, 캐시 적중률을 높이는 데이터의 지역성이 성능의 핵심 요소이다. NUMA 환경에서는 프로세스와 메모리를 같은 노드에 배치하는 것이 중요하다.
        3-3. 병렬 가능한 정도
            - 프로그램의 실행 시간 중 얼마나 많은 부분을 병렬로 처리할 수 있는지가 성능을 결정짓는데, 특정 작업이 이전 작업의 결과에 의존한다면 병렬 실행될 수 없으며 직렬 처리해야한다. 또한, 병렬 처리로 인한 성능 이득이 스레드 생성, 통신, 동기화 등의 오버헤드보다 작은 경우 직렬처리가 더 빠를 수도 있다.
        3-4. 소프트 웨어 관점 성능 예시
            - 분산 처리 프레임워크 : 데이터를 노드 간 효율적으로 분할하고, 코어에서 독립적인 작업을 수행하여 멀티코어의 이점을 극대화시킨다.
            - Lock의 최소화 : 여러 스레드가 공유 데이터를 동시에 접근하는 것을 막는 락을 사용하는 순간 다른 코어들은 작업을 멈추고 기다려야한다. 락을 최소화시키는 것이 성능 최적화의 핵심이다.
    4. 코어 vs 스레드
        4-1. 코어
            - CPU 내부에서 독립적으로 명령을 해석하고 실행할 수 있는 하드웨어 유닛이다. 물리적으로 동시에 처리할 수 있는 작업의 최대 수와 동일하다.
        4-2. 스레드
            - CPU가 실행하는 작업의 가장 작은 단위이며, 프로그램 실행 흐름의 한 갈래이다. CPU의 코어에 의해 실행되는 소프트웨어적인 개념으로 프로세스의 메모리 공간을 공유하면서 독립적으로 실행된다.
    5. 하이퍼스레딩
        - 하나의 물리적인 코어가 두 개 이상의 스레드를 동시에 처리할 수 있게 하는 기술로, 유휴 상태를 활용하여 다른 스레드의 명령어를 가져와 실행하여 최대한 파이프라인을 효율적으로 채우는 기술이다.
        - 코어가 노는 시간을 활용하기 때문에 I/O작업이 많거나 캐시 미스가 잦은 워크로드에서는 전체적인 처리량을 향상시킬 수 있다.
        - 단 물리적인 코어가 늘어나는 것이 아니기 떄문에, 연산 집약적인 워크로드에서는 오히려 성능 향상이 미미하거나 자원 충돌로 성능이 저하될 수 있다.
    6. SIMD & MIMD > 플린의 분류에 따른 병렬 컴퓨팅 아키텍쳐의 분류이다.
        6-1. SIMD
            - 하나의 명령어로 여러 데이터를 동시에 처리하는 기술이다. 이미지 처리, 행렬 연산, 딥러닝 추론 등의 단순 연산을 활용 할 떄 압도적인 성능을 발휘한다.
        6-2. MIMD
            - 여러 개의 명령어로 여러 개의 데이터를 동시에 처리하는 기술이다. 가장 일반적인 병렬 구조로, 멀티코어 CPU, 멀티 소켓 서버, 대규모 분산 클러스터 등이 사용한다.

## 1-6. CPU와 주변 장치의 연결 구조
    CPU는 단일 칩셋으로 동작하지 않고 주변의 장치들과 연결되어 있는데, 구조를 잘 파악하면 병목 현상 파악에 도움이 된다.

    1. Memory Controller
        - CPU와 DRAM간의 데이터를 읽고 쓰는 것을 관리하는 회로로, 현대 CPU는 칩 내부에 통합되어 있다. 메모리 접근 지연시간과 대역폭을 직접적으로 결정짓는 장치이다.
    2. Bus Structure(버스구조)
        - 컴퓨터 내부 구성 요소 간 데이터, 주소, 제어 신호를 전송하는 물리적/논리적 통신 시스템이다. 주소 버스, 데이터 버스, 제어 버스로 구성되어 있다.
    3. PCIe(Peripheral Component Interconnect Express)
        - 고성능 주변 장치를 CPU나 칩셋에 연결하는 고속 직렬 확장 버스로, NVMe SSD나 GPU의 성능은 PCIe의 버전이나 레인 수에 의해 결정된다.

## 1-7. CPU 성능을 판단하는 기준들
    CPU는 코어 수나 클락 수로만 결정되진 않는다. 

    1. Clock Speed (클락 속도, GHz)
        - CPU가 1초 내에 실행하는 사이클의 수를 의미하지만, 사이클의 수는 얼마나 많은 일을 처리하는지 알려주는 것이 아니다.
    2. IPC(Instruction Per Cycle)
        - 하나의 클럭 사이클동안 CPU 코어가 평균적으로 완료하는 명령어의 수를 의미하며, CPU 마이크로아키텍쳐의 효율을 나타내는 지표로 활용된다.
    3. TDP(Thermal Design Power)
        - CPU가 최대 부하 시 발생하는 열을 냉각 시스템이 감당해야하는 최대 전력을 의미한다. 전력 소비량을 나타내면서, 지속적으로 낼 수 있는 최대 성능의 한계를 나타낸다. 높을수록 장시간 고성능을 유지할 여력이 커진다.
    4. Single Core Vs Multi Core
        4-1. Single Core
            - 클럭 속도와 IPC에 의해 결정되며, 암달의 법칙에서 말하는 직렬 처리가 많은 작업에 결정적이다.
        4-2. Multi Core
            - 주요 성능 지표는 총 처리량으로 코어 수 증가, 인터커넥트 패브릭, NUMA 구조, 캐시 일관성 등의 영향을 받는다. 작업 및 데이터 병렬성이 높은 워크로드를 처리할 때 중요하다.

### 추가적으로 그냥 공부해본 내용
- I/O 및 버스 인터페이스
    - I/O Controller를 통해 CPU와 다른 I/O 장치들의 데이터 형식을 맞추고, 빠른 CPU와 상대적으로 느린 I/O 장치들간의 타이밍을 맞춰준다.
    - 버스 인터페이스는 컴퓨터 내부 구성 요소 간 데이터를 전송하는 시스템이지만, 여기서는 보통 시스템 버스를 의미한다. 시스템 버스는 주소 버스, 데이터 버스, 제어 버스의 3가지 요소로 이루어져있다. 시스템 버스를 통해 Load/Store가 이루어져 메모리에서 데이터를 불러오고, 저장할 수 있다.

[^7] : UMA : 여러 개의 CPU가 하나의 메모리에 동일한 접근 속도를 가질 수 있게 설계한 구조로, 동일한 버스로 통신하기 때문에 코어나 CPU가 늘어날수록 병목현상이 심해진다는 단점이 있어, 현재는 대규모에서 잘 사용되지 않고 소규모에서 주로 볼 수 있다.
